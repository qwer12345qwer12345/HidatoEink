# 几何引导的局部窗口排序实验（Issue #14 follow-up）

## 研究问题

验证上一轮发现的“标签相隔 4 步的平均 Chebyshev 距离”能否用于**调整局部窗口访问顺序**，在固定窗口预算下更早发现非冗余反例约束。此实验只调整离线原型的访问顺序，不改生产求解器，不排除任何候选。

## 对照设计

- 基线：按窗口起始标签、结束标签升序访问。
- 特征策略：按窗口局部的 gap-4 平均 Chebyshev 距离降序访问；相同分数时按起止位置确定性排序。
- 反向控制：将基线窗口顺序完全反转，检验收益是否只是来自访问了不同位置的窗口。
- 对每条路径使用 25%、50%、100% 三种窗口配额，每个窗口最多枚举 64 条经验证的替代路径。
- 100% 配额是正确性控制：三种排序必须产生完全相同的合法路径数量、唯一差异集合数量、非冗余约束数和下界，否则程序失败。
- 所有生成的替代路径都必须通过 HamiltonianPaths.isValid；每条差异集合必须非空。输出 DFS 节点数和实际耗时，因为相同窗口数量并不保证完全相同的运行时间。

## 按棋盘尺寸留出测试

除原有 19 条目录/夹具路径外，脚本还生成 15 条确定性的合成验证路径：7×7、9×9、11×11、12×12、14×14 每种尺寸各 3 条。这些尺寸不出现在现有目录语料中。路径从蛇形 Hamilton 路径开始，只应用合法片段反转进行扰动，因此始终保持完整合法性。

这能检验排序策略在新棋盘尺寸上的迁移，但合成路径不能代替更多真实 Hidato 题目。因为 gap-4 特征是从之前的探索性相关中挑选出来的，结果仍应视为后续验证，而不是完全预注册的独立研究。

CI 上传逐窗口 CSV、逐实例汇总 CSV 和 Markdown 报告作为独立 artifact。主要比较 25%/50% 配额下的新增非冗余约束数量、每秒约束产出、DFS 节点数及下界变化；100% 只用于验证不同排序不会改变最终结果。

## 决策规则

- 若特征策略在合成留出集上稳定胜过基线，并在多次运行中减少时间或求解器工作量，再扩展到真实留出题目。
- 若只增加约束数却显著增加耗时，或只在目录语料有效，则不集成生产代码。
- 相关性或更高的约束数量都不构成安全剪枝证明；该工具不改变最优性保证。
