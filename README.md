# 数连 Hidato（HidatoEink）V1.3

面向 Android 墨水屏（E-ink）设备的 Hidato（数连）游戏。玩家从任意已显示数字出发，沿上下左右或对角线相邻格子，依次补出后续数字。

> **本分支的唯一解规则**：生成器只接受已被完整搜索证明仍然唯一的线索删除操作；找到第二个解或求解超时，都保留原线索。优先加载离线已验证题库，其他尺寸使用同样保证唯一性的在线生成器。**唯一解是硬约束，初始线索尽量少是优化目标**；不声称得到全局最少线索。

## 当前功能

- 自定义 **4～15 行 × 4～15 列**棋盘，支持长方形棋盘。
- 简单、中等、困难三档难度；首次启动显示可跳过的玩法教程。
- 点击已有数字选中焦点，再点击相邻空白格尝试填入下一个数字；错误点击会累计错误次数。
- 可随时改选另一已显示数字作为起点；支持撤销最后一次玩家填数、随机提示及重置本关。
- 大棋盘支持横向和纵向滚动；格子点击区域至少 48dp。
- 自动保存游戏进度；可从主界面继续未完成的关卡。
- 通关后显示错误次数、提示次数，保存成功后展示结算。

**操作说明**：本版本采用“即时判定”玩法，空白格只有与内置答案中的下一个数字一致且相邻时才会填入；它不是允许玩家自由填写所有可能数字、最后再统一验题的传统纸笔模式。提示会随机揭示一个尚未显示的数字，并将焦点移到该格。

## 难度与线索

| 难度 | 删除线索时的下限 | 实际行为 |
| --- | --- | --- |
| 简单 | `ceil(总格数 × 35%)` | 保留相对较多线索，但先满足唯一解 |
| 中等 | `ceil(总格数 × 20%)` | 尝试移除更多线索；达不到目标时保留更多 |
| 困难 | 2（只固定 1 和终点） | **持续尝试删除，只有证明仍唯一才接受**；不会无条件删到两个 |

这里的下限只规定“最多尝试隐藏到哪里”，不是承诺一定达到这个数量。不同完整答案路径需要的线索数可能差异很大。困难档采用随机顺序的单线索删除，可能达到**局部不可再删**，但在验证超时、提前截止、或换一种删除顺序的情况下还可以优化；**不声称求得全局最小线索集**。

在线生成默认设置约 2 秒线索优化预算，每次验证最多约 250 ms；耗尽时保留无法验证的线索。因此时间预算影响线索稀疏程度，**不会降低唯一解要求**。完整路径生成阶段仍可能重试，不属于严格的 2 秒总时限。

## 内置离线题库

本分支自带 `app/src/main/assets/unique-puzzles.tsv`，目前包含 **18 道已离线验证为唯一解**的题目，覆盖 4×4、5×5、6×6、8×8、10×10 与 15×15 的部分难度组合；8×8 的中等与困难档各有 2 道。没有相应尺寸/难度时，自动使用经过唯一性验证的实时生成器。题库目前数量较少，重复开局可能抽到同一关；并不是完整关卡内容库。

当前离线样例的困难档线索数为：4×4 **4 个**、5×5 **6 个**、6×6 **8 个**、8×8 **最少 17 个**、10×10 **27 个**、15×15 **79 个**。这是从有限次数的随机候选中选出的结果，**不是数学最小值，也没有统一的实际解题难度评分**。

## 核心算法（以当前代码为准）

### 1. 完整路径生成

`HamiltonianPaths.randomTour()` 使用**带随机扰动的 Warnsdorff 贪心策略**：

1. 在棋盘上随机选择起点。
2. 在当前格子的 8 方向未访问邻居中，优先选择后续未访问邻居数最少的格子；随机扰动用于打破评分接近的情况。
3. 若中途无法继续，则重新尝试；成功时得到一条覆盖所有格子的合法 Hamilton 路径。
4. 使用 `HamiltonianPaths.isValid()` 校验路径没有重复格子、没有漏格且每步相邻。

当前实现**不是**旧 README 描述的“蛇形路径 + 50～200 次段反转”。生成器的 2 秒预算也不是整个路径生成过程的严格超时上限：`randomTour()` 使用重试循环。

### 2. 可返回反例的准确求解器

`HidatoSolver.findAlternative()` 已知生成器的完整正确答案，因此专门搜索是否存在**另一条不同的完整路径**：

- 所有初始给定数字的格子从一开始就预留，不能被其他数字提前占用。
- 逐格 DFS，固定数字优先强制落位，检查到下一已知数字的切比雪夫距离，每 5 步进行剩余区域连通性检查。
- 搜索结果严格区分 `Found(path)`（给出一条可检查的第二答案）、`Unique`（完整证明不存在第二答案）与 `Unknown`（时间或节点预算耗尽）。
- 保留 `countSolutions()` 供测试使用；它在预算耗尽时返回 `-1`，绝不将未知当成唯一。

### 3. 可解释的线索优化

`PuzzleGenerator` 与 `HidatoSolver` 协作，但是各自承担单一职责：

1. 从完整路径、全部数字可见开始（显然唯一）。
2. 随机选择一个非首尾线索，暂时隐藏。
3. **已知反例检查**：如果此前保存的第二答案依然满足所有剩余线索，直接证明多解，不需要 DFS。
4. **局部路径反转检查**：若一个连续路径片段反转后两端仍接得上，就构成另一个合法完整答案；如果已隐藏所有能区分两条路径的数字，同样直接证明多解。这种判断只用于**证明多解**，不能代替唯一性搜索。
5. 否则请完整求解器验证：`Unique` → 永久隐藏，`Found` → 恢复并缓存反例，`Unknown` → 恢复。
6. 达到难度下限、遍历完成或预算耗尽时结束。

每次成功删除都有完整的唯一性证明。因此即使中途停止，题目仍然唯一；区别仅在于留下了多少线索。生成统计 `GenerationStats` 记录通过验证的删除数、反例快速拒绝数、求解器调用次数与未知结果数，避免把无依据的优化“效果”写进文档。

**为什么目前不做精确最小击中集 / SAT？** 它们值得继续研究，但必须先建立正确性基线、可复现题库和性能基准。当前这套“反例驱动的贪心删除”是更容易验证的第一阶段实现，并**没有假装实现全局最优**。

### 4. 离线预生成与最终验证

`tools/offline/PreGenerate.kt` 对同一尺寸/难度使用多个随机候选进行生成，选择给定数字数更少的候选；如果线索数相同，优先选择未决验证次数更少者。选出的题目需要通过**额外一次独立调用、较高预算的完整唯一性验证**，否则工具报错，不会输出到标准输出。

需要 JDK 17+ 和 Kotlin CLI 1.9.x，在仓库根目录运行：

```bash
# 输出一行 TSV：行、列、难度、按数字顺序的位置索引、给定数字列表
bash tools/offline/pregenerate.sh 8 8 HARD 10 10000 42

# 将成功验证的题目追加到 APK 内置题库
bash tools/offline/pregenerate.sh 8 8 HARD 10 10000 42 >> app/src/main/assets/unique-puzzles.tsv

# 验证整个内置题库：如果有坏数据、多解或验证超时，则以失败退出
bash tools/offline/verify-catalog.sh
```

运行日志输出到 stderr，只有通过最终验证的数据才写入 stdout。重复运行可能产生相同题目；目前没有自动去重。TSV 的完整路径索引是从 0 开始，给定数字编号从 1 开始。

## 唯一解生成：历史尝试与现状

这个项目**曾实现过**“隐藏一个数字 → 调用求解器检查是否仍只有一个解 → 多解则恢复”的方案，并非从未尝试过唯一解生成。

相关 Git 历史：

1. [`6660ae8` — perf: optimize hidato solver search state](https://github.com/qwer12345qwer12345/HidatoEink/commit/6660ae842ed86faf1303bdb9824945635cad131d)：对求解器的邻接表、BFS 和连通性搜索状态做性能优化；当时生成器仍调用求解器做唯一性检查。
2. [`3aca292` — feat: generate puzzles without uniqueness checks](https://github.com/qwer12345qwer12345/HidatoEink/commit/3aca292d5ae8cf9dab85538cc50dacc406bdc72d)：从生成器中移除每次隐藏后的唯一性检查，并相应调整生成测试。
3. [`0cdc67f` — refactor: decouple puzzle generation from solver](https://github.com/qwer12345qwer12345/HidatoEink/commit/0cdc67fce2ca6b58cdc113c2aa8c2b4dc84856f5)：进一步移除生成器对求解器的依赖注入。

旧版生成器的源码注释记录了当时的主要困难：随机隐藏容易产生较大的线索间隔，令求解验证代价增高，线索压缩难以达到预期比例。此外，旧求解器未从一开始预留所有未来固定线索的格子，存在把未来线索格误用作其他数字位置的风险。本分支同时修正固定线索约束与预算判定，并使用小棋盘独立暴力枚举进行交叉测试。

本分支已经恢复了唯一解硬约束，并增加反例缓存及离线候选筛选。进一步的全局最少线索证明、稳定解题难度评分以及完整尺寸题库仍属于未来工作。

## 进度保存与已知限制

- **Room 单槽位存档**：保存棋盘尺寸、难度、完整答案路径、初始线索、已揭示提示、玩家填数顺序、进度及统计数据；开始新关卡时覆盖旧存档。
- **自动保存**：正确填数、错误计数变化、撤销、提示、切换可见数字焦点等状态变化会触发保存；通关后等待存档写入成功才显示结算。
- **读写顺序**：保存任务在应用级协程作用域中运行，并通过 Mutex 串行化；读取会等待此前已入队的写入操作。
- **重置本关**：当前**仅重置内存、不立即保存**。如果重置后未进行其他会触发保存的操作就退出，重新进入时可能恢复旧进度。
- **焦点恢复**：当前存档**不单独保存 `focusedCell`**；恢复时默认选中玩家最后填写的格子，而非退出前最后点击的线索。
- **DataStore**：记录上次选择的行列尺寸和难度，以及是否已完成或跳过首次教程。

## 本地构建与测试

准备 JDK 17、Android SDK（compileSdk 34 / build-tools 34.0.0），并在项目根目录的 `local.properties` 中配置 Android SDK 路径（如 `sdk.dir=/path/to/Android/Sdk`）。

```bash
# 编译 Release APK
./gradlew assembleRelease

# APK 路径
# app/build/outputs/apk/release/app-release.apk

# 运行本地 JVM 单元测试
./gradlew test
```

当前 Release 配置开启 R8 代码压缩与资源裁剪，**但使用调试签名**，适合本地安装测试，不适合作为正式发布签名。构建脚本目前还限制了 `arm64-v8a` ABI。

测试代码覆盖路径合法性、求解器与简单暴力枚举的结果交叉验证、第二答案的合法性、超预算处理、线索唯一性以及游戏规则。可用 `bash tools/offline/verify-catalog.sh` 逐条重新证明内置的 18 道题目只有一个解。尚需在目标 Android/墨水屏设备上执行构建与性能测试。
