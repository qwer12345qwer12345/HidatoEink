# 固定路径 S 的最少线索算法与验证记录

## 问题不是“尽量随机删数字”

固定一条完整合法路径 `S=(s_1,...,s_N)`。用二元变量 `x_n` 表示数字 n 是否作为线索显示：

- `x_1=x_N=1`（本游戏强制保留两个端点）。
- 优化目标：`min sum(x_n)`。
- 对任何其他合法完整路径 `T != S`，定义差异集合
  `D(T)={n | T[n-1] != S[n-1]}`。
- 唯一解的必要且充分条件是：对每一条 `T != S` 都有
  `sum(x_n, n in D(T)) >= 1`。

**必要性**：如果 D(T) 中一个数字都没给出，T 满足所有已给线索，因此题目多解。

**充分性**：任何其他合法路径 T 至少与某个已给线索位置不同，因此不可能同时满足题面。

这个模型叫做 **Minimum Hitting Set**（最小击中集），也是唯一解谜题研究中“unavoidable sets / 不可避免集合”思路的核心。它不是单纯的启发式评分。

相关论文（方法借鉴，不声称 Sudoku 的数字结论适用于 Hidato）：

- McGuire, Tugemann & Civario, *There Is No 16-Clue Sudoku: Solving the Sudoku Minimum Number of Clues Problem via Hitting Set Enumeration*, Experimental Mathematics 23(2), 2014. DOI: https://doi.org/10.1080/10586458.2013.870056
- Tjusila、Besançon、Turner 与 Koch，*How many clues to give? A bilevel formulation for the minimum Sudoku clue problem*（Operations Research Letters, 2024，DOI: https://doi.org/10.1016/j.orl.2024.107105），相关实现：https://github.com/gtjusila/minimum-sudoku

## 为什么不枚举所有可能的 T？

每一种其他合法完整路径都形成一条约束。全部列举非常昂贵。

因此采用 **主问题 + 分离子问题**：

1. **主问题（HittingSetMaster）**：对已知差异集合按线索数从少到多枚举。用不相交反例打包与频率覆盖计数两个可证下界的最大值跳过不可能的较小基数；递归时仍以不相交约束剪枝。只有完整搜索才返回确定答案。
2. **分离子问题（HidatoSolver）**：将候选线索交给求解器。
   - 返回 `Found(T)`：`T` 是违反唯一性的具体证据；加入约束 `sum_{n in D(T)} x_n >= 1`，继续优化。
   - 返回 `Unique`：当前候选唯一，且主问题已经证明没有更小的候选满足所有已知必要约束；**它就是固定 S 的全局最少线索集合**。
   - 返回 `Unknown`：不作任何唯一性推断，结束优化并保留先前经验证的题目。
3. 预先从原始路径构造必要约束，不调用求解器：
   - **合法片段反转**：反转 S 的任意内部片段，当两条新边界边均相邻时得到另一条合法完整路径。
   - **局部路径替换**（本 PR 新增）：对 S 中长度受限的窗口重新排序，只要新排列仍连接**同一对边界锚点**，它就是另一条完整合法路径；其差异集合同样是必要约束。片段反转只是"两条边交换"的特例，此方法在首次求解器调用之前暴露多得多的不可避免集合。窗口上限 8、每窗口枚举上限 64，15×15 的播种成本约 12ms；截断只会少产生约束，绝不会凭空产生约束，因此与数学安全性无关。
4. 所有约束只保留包含关系下更强的**集合极小项**。如果 `U⊆V`，满足击中 `U` 的线索必定也击中 `V`；所以 V 可删除。

### 固定线索区间的等距传播（Issue #9）

设当前数字为 `a`，所在格子为 `p`，下一个固定线索为数字 `b`，所在格子为 `q`。从 `a` 到 `b` 还剩 `b-a` 步，故必要条件是：

`d∞(p,q) ≤ b-a`。

当距离恰好相等，即 `d∞(p,q) = b-a` 时，每一步都必须令 Chebyshev 距离减少 1。原因是一次八方向移动最多只能使该距离减少 1；若要在恰好 `d∞(p,q)` 步到达 `q`，每一步都必须达到这个最大减量。因此，只需尝试能让距离恰好减一的邻格；访问过的格子以及被未来固定线索预留的格子仍然必须排除。

**与旧实现的关系：** 原有逐候选距离上界已经隐含了这条等距性质。本次变更把它前移到候选生成阶段，避免把不可能的邻格送入候选检查，并跳过对同一距离条件的重复计算；它不是一条新的数学下界，也不改变 `Found / Unique / Unknown` 的含义。若区间还有额外步数，仍使用原来的安全距离上界，不做等距强制。

正确性测试覆盖：

- 4×4 边界上的水平等距区间和对角线等距区间；
- 最短路线上的某个邻格被未来固定线索占用时，不能误用该格；
- 穷举全部 2×3 合法完整路径及每一种固定首尾数字的线索子集，并与不使用生产剪枝的独立路径枚举器逐项对照。

本次不预先声称有多少性能提升。CI 会在相同语料、JVM 配置、超时和节点预算下分别运行关闭该传播的 baseline 与开启传播的 exact 变体，并上传两组原始数据及中位数摘要；只有配对结果支持时才报告速度收益。

### Issue #9 配对消融结果（CI run #87）

在同一 CI runner（JDK 17.0.20.1+1、Linux amd64）上，对 baseline（关闭显式等距传播）和 exact（开启传播）使用相同固定语料、30 秒预算、相同节点预算，各重复 3 次。以下为优化器耗时中位数：

| 实例 | Baseline | Exact | 变化 |
| --- | ---: | ---: | ---: |
| 5×5 easy | 1 ms | 1 ms | 未测出差异 |
| 6×6 easy | 1292 ms | 1278 ms | −1.1% |
| 8×8 easy | 4586 ms | 4438 ms | −3.2% |
| 15×15 hard | 9675 ms | 7971 ms | −17.6% |

这几组实例的主问题节点数和分离器调用数在两个变体间完全相同（分别为 52/5、134/14、18111/6、69/2）。因此，目前证据支持的是端到端耗时降低，而不是主问题节点减少；基准 CSV 没有记录求解器内部 DFS 节点数，不能进一步声称内部搜索树变小。5×5 没有可测收益，6×6 收益较小，8×8 与 15×15 的中位数更低。

两个变体的最优性/停止状态一致：5×5 与 6×6 均证明最优；8×8 与 15×15 仍为 `SOLVER_UNKNOWN`，不得报告为最优。该结果基于单个 runner、每种配置 3 次运行，属于有限的配对实验，不保证所有棋盘都会加速。保留此优化的理由是它不改变答案或证明语义，并在较大实例上显示出可复现的耗时改善。

### 无须枚举即可证明的下界

设已知差异集合中找到 `k` 个**两两不相交**的集合 `D₁,…,Dₖ`。要排除这 `k` 条真实替代路径，至少需要从每个集合保留一个**不同的**线索，因此：

`线索数 ≥ k + 2`（其中 2 是强制首尾线索）。

寻找这 `k` 个集合使用确定性的**短集合优先贪心打包**。这个策略未必能找出最大的 `k`，但无论找到多少，结果始终是安全的数学下界，而非猜测。如果它恰好等于一个已经通过完整唯一性验证的题目的线索数，则可以立即报告 `PROVED_MINIMUM`，无需再运行击中集主问题。若不相等，就用它跳过所有必然不可能达到的较小线索数，并继续正常求解。

实现位于 `MinimumClueOptimizer.disjointWitnessLowerBound()`、`coverageWitnessLowerBound()` 与 `witnessLowerBound()`；两个安全下界取最大值，不因棋盘尺寸切换算法，也不引入额外求解框架。参考 [McGuire 等人的最少线索研究：相互不交的 unavoidable sets 下界](https://www.math.ie/checkerold.html)。

## 停止结果含义

- `PROVED_MINIMUM`：对**给定完整路径 S 和端点固定规则**严格证明达到最少线索。不是所有可能的完整路径共同的全局最少。
- `TIME_LIMIT`：达到计算时间上限，返回已经独立确认唯一的初始或改进候选；没有最优性证明。
- `MASTER_NODE_LIMIT`：主问题预算不足，同上。
- `SOLVER_UNKNOWN`：分离求解器不能完成验证，同上。

不能把 `Unknown` 当成 `Unique`；不能把“线索较少”描述成“已经证明最少”。

## 频率覆盖下界与验证（PR #5）

对于 (m) 条非空反例约束，若任一内部数字最多出现在 (F) 条约束中，则选择 (k) 个线索最多覆盖 (kF) 条约束，故任何击中集都必须满足 (k \ge \lceil m/F \rceil)。实现逐个统计每个数字在约束中的出现频率，计算该计数下界，再与不相交反例打包下界取最大值。两者都是安全下界；**下界本身不能证明唯一性或最优性**。

- 三条约束 `{2,3}`、`{3,4}`、`{2,4}` 的不相交打包下界为 1，频率覆盖下界为 2。
- 100 组确定性随机小型集合族使用独立穷举求真最小击中集，验证组合下界从未超过真值。
- 在题库 18 条路径的初始合法片段反转约束中，新下界超过旧打包下界的数量为 0/18；不据此宣称真实题库运行时间加速，新增反例后的效果也尚未量化。

## 为什么它只在离线工具中使用？

精确击中集本身是 NP-hard，分离子问题也需要求解大规模路径约束。即便 8×8 也可能因不同路径而耗时悬殊。因此：

- 无论 4×4、8×8 还是 15×15，离线精确优化器都使用**同一套算法与数据结构**。固定端点与谜题尺寸只通过 `Puzzle` 输入，而不是特殊分支。
- 使用 JDK 标准的 `java.util.BitSet` 记录线索差异集合；其大小随棋盘自动增长，**不再存在 64 格上限**，无需自定义多个 `Long` 的掩码类。
- 大棋盘证明最优仍可能需要指数级时间。到达主问题节点上限、求解器预算或时间上限时，返回**已经验证唯一的上界**，并明确标注“未证明最优”；不会因为超时损害唯一性。
- Android UI 不运行精确优化：玩家打开关卡时仍加载预生成题库，未覆盖的尺寸依旧使用受预算约束的唯一解生成器。

## 可复现最少线索基准（Issue #8）

基准语料固定在 `tools/offline/minimum-clue-benchmark.tsv`，包括：

- 3×3 小棋盘：独立枚举全部 128 种端点固定的线索子集，并直接枚举完整路径作为正确性 oracle；此检查不调用生产求解器或其剪枝。
- 已知证明最少为 4 个线索的 4×4 中等题，作为每次运行的证明回归。
- 5×5、6×6、8×8 和 15×15 题库实例；15×15 覆盖 64 格以上的统一 `BitSet` 路径。

运行命令（需要 JDK 17 和 `kotlinc`）：

```bash
bash tools/offline/benchmark-minimum-clues.sh \
  app/src/main/assets/unique-puzzles.tsv \
  tools/offline/minimum-clue-benchmark.tsv \
  /tmp/minimum-clue-benchmark-exact-raw.csv \
  /tmp/minimum-clue-benchmark-exact-summary.csv \
  30000 3 1000000 50000000 exact

# Same corpus and budgets, with exact-distance propagation disabled as the control.
bash tools/offline/benchmark-minimum-clues.sh \
  app/src/main/assets/unique-puzzles.tsv \
  tools/offline/minimum-clue-benchmark.tsv \
  /tmp/minimum-clue-benchmark-baseline-raw.csv \
  /tmp/minimum-clue-benchmark-baseline-summary.csv \
  30000 3 1000000 50000000 baseline
```

参数依次是题库、语料、逐次原始 CSV、汇总 CSV、每次时间预算（毫秒）、重复次数、主问题节点预算、oracle 节点预算和变体（`baseline` 或 `exact`）。CI 对两个变体使用相同语料、JVM 配置和预算，分别上传原始 CSV 与中位数摘要。固定路径以 SHA-256 标识，不依赖运行时随机数。原始 CSV 记录 JVM/操作系统、尺寸、初始/最终线索、证明状态、认证下界、耗时、主问题节点、oracle 调用、反例数、保留约束数及超时/Unknown 状态。汇总 CSV 报告中位数、线索数范围、证明次数和各停止状态，以保留运行方差而不是只挑选最好的一次。

当小棋盘或已知 4×4 参考值已经能证明最优时，结果必须与参考最小值一致；超时、节点预算耗尽和 `UNKNOWN` 只会记为未证明，不会升级成最优。CI 会上传原始数据和中位数摘要作为每次运行的基准 artifact。耗时受 runner/JVM 影响，因此不把未经同一环境复测的时间写成固定性能承诺，也不把未实际运行的数字提交为基线。

## 验证记录（本次变更：PR #2）

**目标和边界**：只优化给定完整路径 `S` 的初始线索，不更换 `S`。保留首尾数字的规则；所有当前棋盘尺寸都采用同一套 `BitSet` 模型。计算量大时只返回已验证唯一的上界，绝不虚报数学最优。

**为什么引入这套模型**：逐个删除线索只能找到“单独再删一个就多解”的组合，无法判断另一组不同的给定数字是否更少。主问题枚举较小的击中集，求解器给出有证明的替代路径约束，才能在完成搜索时证明固定路径的全局最少线索数。

**改动及核验方法：**

- `MinimumClueOptimizerTest.kt` 对三个 3×3 完整解分别穷举全部 `2^7=128` 种内部线索组合，用独立暴力路径枚举算出真正最小值，再比较优化器给出的 `PROVED_MINIMUM`；同时覆盖 4×4 最优性、预算耗尽不得标记最优，以及局部反转约束的合法性。
- 8×8、9×8（超过旧版 64 格阈值）、15×15 使用相同优化入口；测试严格预算下仍可安全返回完整线索上界，并验证超过第 64 个数字不会发生位重叠。**不将“能够进入算法”误写为“大棋盘已证明最优”。**
- 实际题库的 **4×4 中等档**在相同路径下由 **5 个已知数字减为 4 个**（1、11、15、16），离线优化器对该路径输出 `PROVED_MINIMUM`。完整题库现含 **18 道**，复验均为唯一。


### 验证记录（PR #3：互不相交反例的可证下界）

**变更内容**：不改变最小击中集模型，只提取已知反例中的两两不相交集合来计算下界；命中已验证唯一的上界时直接证明最优。所有棋盘尺寸共享同一 `BitSet` 实现。

**可独立核验的测试**：

- 对 100 组随机小型集合族，使用独立全枚举找出真正的最小击中集大小，验证打包下界**从未超过**真实最优值。
- 内置 4×4 中等档：已验证唯一的 4 个线索恰好由两个互不相交的反转证据强制（另有固定首尾）。数学上至少需要 4 个，而当前有 4 个，因此无需主问题展开：`masterNodes=0`、`solverCalls=1`、`PROVED_MINIMUM`。与旧版同一条路径 `masterNodes=2` 相比，避免了主问题搜索。
- 原有 3×3 与 4×4 最少线索对照、8×8/9×8/15×15 通用尺寸、预算超限不得虚报最优、18 道题库唯一性复验继续由 CI 运行。

**适用边界**：下界小于当前已知唯一的线索数时，只能减少搜索，**不能仅凭这个下界认定已经最优**。该优化不是 NP-hard 问题的通用多项式解决方案。

**遗留问题**：大棋盘上最小击中集仍可能需要指数级计算；时间/节点限制后的结果不是数学最优性证明。没有对 8×8 或 15×15 的固定路径最少线索数做普遍性能保证，也没有墨水屏实机基准数据。

**维护规则**：每轮只合入一项有正确性依据或可重复收益的算法优化；集中完成代码、测试、本文和过时文档清理，以**单个原子提交**形成 PR，CI 全部通过后才 squash 合并。旧版本演进留在 Git/PR 历史，不重复累积在 README 或独立短篇文档中。

## 验证记录（本 PR：局部路径替换播种约束）

**目标**：不改变最小击中集模型与停止条件，只在搜索开始前用"局部路径替换"扩充种子约束族。每个替换都是一条完整合法路径（同锚点、同格子集合、相邻性成立），因此其差异集合是不可回避集合，数学上与片段反转完全同源。

**可独立核验的测试**（`LocalReplacementWitnessesTest`）：

- 3×3～8×8 随机路径上，每个被播种的替换必须通过 `HamiltonianPaths.isValid`、必须与参考路径不同、必须保留首尾端点。
- 播种约束恰好等于替换路径差异集合的去重结果。
- 3×3 全枚举对照（与既有 `MinimumClueOptimizerTest` 相同的独立暴力 oracle）：播种后仍精确得到真实最少线索数。
- 播种后的不相交下界不弱于仅用反转的下界。

**对照基准**（Windows 11 / JDK 17.0.20.1 / 16 逻辑核 / 相同输入与预算 / 5 次重复取中位数；对照为 master 2e0760f，命令见上节）：

| 实例 | 对照（反转） | 替换播种 | 结论 |
| --- | --- | --- | --- |
| 6×6 中等（题库） | PROVED 10 线索，40 次求解器调用 / 38 反例，5707 主问题节点，72ms | PROVED 10 线索，19 次调用 / 17 反例，2575 节点，**35ms** | 相同证明，耗时约减半 |

播种成本：4×4 约 1ms，8×8 约 2ms，15×15 约 12ms（产出 90 条非冗余约束，其中 18 条为新增）。所有既有测试（3×3/4×4 最少线索对照、预算耗尽不得虚报、>64 位 BitSet、题库唯一性复验）不变通过。

**适用边界**：播种只增加初始约束，不保证任何大棋盘从 SOLVER_UNKNOWN 变为 PROVED_MINIMUM；上表如实保留 Unknown。窗口与枚举上限是工程取舍，不是数学参数。

## 固定路径几何与反例质量分析（Issue #13）

新增的独立离线分析工具比较合法片段反转、带窗口上限的局部路径替换原型和完整求解器返回的真实替代路径。它记录直线段/转弯、附近标签几何距离、差异集合大小与重叠、非冗余约束新增量，以及各阶段的互不相交打包下界。3×3 样例还会穷举当前约束族的最小击中集以交叉检查下界。

复现命令和指标定义见 [固定路径几何分析说明](fixed-path-geometry.md)。CI 在每次运行时生成逐见证 CSV、逐实例汇总 CSV 和带相关性分析的 Markdown 报告，并作为独立 artifact 上传。所有性能/相关性结论必须来自实际运行数据；UNKNOWN 不等于唯一解，相关性也不构成安全剪枝证明。

## 击中集主问题的增量覆盖记账（Issue #11）

**变体与结论**：`HittingSetMaster` 原先在每个搜索节点重新扫描全部约束（`BitSet.intersects` × m）。本变更把它改为增量覆盖记账：预先构建"数字 → 包含该数字的约束"关联表；分支选中数字时递增对应约束的命中计数并把新覆盖的约束从**保序双向链表**中摘除，回溯时按 LIFO 日志原位恢复。节点内只需扫描"尚未覆盖"的约束，且最小割基数预先算好。遍历顺序、答案和节点数与逐节点全扫描实现**逐位一致**（`HittingSetMasterIncrementalTest` 用测试侧复刻的 rescan 参考实现逐实例断言 kind/mask/nodes 相等）。

同题消融的其他变体（测试侧 `HittingSetAblationReference`，仅用于实验，未进入生产）：

- **A 覆盖频率排序分支**（短割不变，割内数字按当前未覆盖约束命中数降序尝试）：FOUND 型负载节点数下降（如 synth-a 45→27、synth-b 165→84），但每个节点需额外统计全部活跃数字频率，大实例墙上时间反而变慢（synth-c 82ms vs 增量 10ms）。
- **B 最受约束割规则**（活跃割中"最强数字覆盖数"最小者优先）：节点数显著上升（synth-d 5382→84763、synth-e 148573→267413），明显更差。
- **D 频率覆盖节点下界**（ceil(活跃约束数 / 最大数字频率)）：节点数小幅下降（synth-c 12231→9989），但额外扫描使总时间仍高于纯增量（24ms vs 10ms）。

**采纳**：仅增量覆盖记账（变体 C）进入生产。它不改变任何遍历或语义，纯降低每节点成本。

**基准**（Windows 11 / JDK 17.0.20.1 / Gradle 8.7 / 相同输入 / 5 次重复取中位数；命令见下）：

| 实例（合成重叠小割族） | rescan 基线 | 增量记账 | 节点数 |
| --- | ---: | ---: | ---: |
| synth-c（33 数字 / 180 割） | 30ms | **10ms** | 12231（相同） |
| synth-d（41 数字 / 300 割） | 7ms | **4ms** | 5382（相同） |
| synth-e（49 数字 / 450 割） | 339ms | **112ms** | 148573（相同） |

真实题库路径的初始约束族（4×4～15×15，5～90 条约束）上主问题节点数 ≤ 2.3 万、耗时亚毫秒到数毫秒，主问题仍不是端到端瓶颈；全量端到端基准（`MinimumClueBenchmark`）的线索数、证明状态、oracle 调用数与 master 节点数和 master 基线完全一致（耗时差异在噪声内）。**已发现的规模上限**：主问题的真正扩展瓶颈是共享 `visited` 状态集合的内存（约等于节点数 × 每状态 BitSet 字宽），18 条题库路径的块状合并实例（1076 位掩码 × 5×10⁶ 节点预算）在默认测试 JVM 堆内先于节点预算 OOM——扫描成本并非首要限制。
